Cross-cutting patterns

Three behaviors that show up on nearly every screen: how a status is allowed to change, how a change gets recorded, and how a projected figure stays visually distinct from a confirmed or actual one.

Status transitions
Not every status is user-editable, and not every transition is available from every state. A departure's status is a deliberate choice with real consequences; a payment's status is a fact derived from receipts and shouldn't be set by hand at all.

Derived — payment status

Partially paid 🔒 Calculated from receipts
No dropdown — this status isn't set by a person. It's recalculated automatically whenever a receipt is applied, so it can never drift out of sync with the actual balance.
Consequential transitions get a confirmation
Cancelling a departure doesn't cancel its client trips or supplier obligations — those are tracked independently on purpose. The confirmation exists to state that plainly before the click, not to slow people down generically.

Audit trail
Every entry is a plain statement of what changed, by whom — no narration, no apology. Financial and correction entries are tagged so they can be filtered; a correction to an already-confirmed fact is visually distinct from a routine edit.

A "Correction" is a distinct category from a normal edit — it's reserved for changing a fact that was already confirmed, always carries a reason, and never silently overwrites the prior value in the visible history.
Projected vs. confirmed vs. actual
The same figure can exist in three states of certainty at once. The distinction is carried by fill and weight — dashed and muted, solid teal, solid navy and bold — never by hue alone, so it still reads correctly for someone who can't distinguish color.
