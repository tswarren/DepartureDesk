Empty states

Every empty state explains what's missing and what to do about it — in the interface's voice, never apologetic or vague. Not all of them need a call to action.

No data yet — actionable
The most common case: nothing has been created here yet, and the fix is one specific action. The dashed border signals "not yet populated," distinct from a solid-bordered card that's simply empty by filtering.

Inline empty states — within an existing section
When the empty state lives inside a card that already has other content around it (like a profile page), it doesn't need its own full treatment — left-aligned, smaller icon, no dashed frame competing with the card's own border.

Permission-safe empty states
The tricky case: administrator-only notes must be invisible to staff "including counts and empty states." That means a staff member looking at a party with only an admin-only note must see the exact same screen as a party with genuinely zero notes — not a hint, not a different count, not a slightly different message.

Error vs. empty — don't conflate them
An empty state means the request succeeded and there's genuinely nothing there. A failed request is a different problem with a different fix, and should never be dressed up as an empty state.
