# Architecture decisions

Moved from [AGENTS.md](../../AGENTS.md), which points here. Every ADR and which govern new work. These rules are binding when a task touches this area.

Accepted ADRs under `docs/adr` are authoritative for the technical decisions they record, unless a decision log entry or a later ADR supersedes them. Read the relevant ADR before designing or changing its domain. ADRs 0016 to 0018 record the charter's Phase 0 code conflicts. They govern new work from Slice 1 step 1 onward. Until a Slice 1 step implements them, the shipped code follows the ADRs they supersede.

- [ADR 0001: Money and currency representation](../adr/0001-money-and-currency.md) accepts `money-rails`, `bigint` minor-unit persistence, explicit currencies, strict parsing, and explicit historical conversion facts. The gem is installed. [M3C](../planning/m3-supplier-planning/m3c-cost-terms-and-forecasts.md) shipped the first draft Supplier cost monetary tables; posted client/supplier ledgers, Obligations, and Payments are not shipped. Do not persist functional-currency translations. The MVP commercial contract later limits each Departure to one operating currency and excludes FX.
- [ADR 0005: Agency identity](../adr/0005-agency-identity.md) is the tenancy, invitation, session, permission, and office-context contract, as amended by ADR 0016 (one agency time zone, optional offices) and ADR 0017 (user types and per-user permissions). Implement it with those amendments. Do not invent alternatives.
- [ADR 0006: Separate identity domains](../adr/0006-separate-identity-domains.md) rejects a universal Party identity and separates AgencyUser, Client, Supplier, and Traveler contexts. It is an accepted future-domain boundary, not permission to implement those records before an accepted slice.
- [ADR 0007: Departure as operational root](../adr/0007-departure-operational-root.md) accepts Departure as the dated operational root and defers Travel Program. Do not add a Travel Program table, route, model, or foreign key until a later accepted slice names that work.
- [ADR 0008: Supplier Arrangement version topology](../adr/0008-supplier-arrangement-version-topology.md) accepts stable Arrangement and child identities with per-version definitions. M3A draft topology is implemented; activation and successor behavior are shipped with M3D; [M3D.7](../planning/m3-supplier-planning/m3d7-activated-definition-immutability.md) freezes exact-version definition graphs after leaving draft. **Its code was deleted in charter Phase 1 (D-66)**; for new work, ADR 0018 governs.
- [ADR 0009: Supplier contracting and service-provider roles](../adr/0009-supplier-contracting-and-service-provider-roles.md) accepts contracting Supplier, computed Service Provider, Arrangement contact, and inactivation-dependency meanings. M3A Supplier-role behavior is implemented; later dependency extensions are deferred. **Its code was deleted in charter Phase 1 (D-66)**; for new work, ADR 0018 governs.
- [ADR 0010: Supplier capacity ledger and projection](../adr/0010-supplier-capacity-ledger-and-projection.md) accepts stable Capacity Pool identity, immutable capacity events, scheduled effectiveness, reconciliation, and rebuildable projections. [M3B](../planning/m3-supplier-planning/m3b-supplier-capacity.md) shipped the implementing persistence and engine; Arrangement activation and Staff event UI are shipped with M3D. **Its code was deleted in charter Phase 1 (D-66)**; for new work, ADR 0018 governs.
- [ADR 0011: Supplier cost definitions and forecast evaluation](../adr/0011-supplier-cost-definitions-and-forecast-evaluation.md) accepts exact-version cost sources, staged definitions, constrained components, planning assumptions, and derived forecasts. [M3C](../planning/m3-supplier-planning/m3c-cost-terms-and-forecasts.md) shipped the implementing slice; Arrangement activation and effective contracted terms are shipped with M3D. **Its code was deleted in charter Phase 1 (D-66)**; for new work, ADR 0018 governs.
- [ADR 0012: Arrangement activation, Reservations, and confirmations](../adr/0012-arrangement-activation-reservations-and-confirmations.md) accepts activation manifests, successor copying, Reservation history, confirmation evidence, and the M3D confirmation-triggered commitment core. [M3D](../planning/m3-supplier-planning/m3d-activation-reservations-confirmations.md) ships the implementing slice after shipped [M3D.0](../planning/m3-supplier-planning/m3d0-planning-workspace-compression.md). A 2026-09-18 supersession note records that [ADR 0013](../adr/0013-supplier-operational-commitments-deadlines-exposure-and-ending.md) supersedes “manual opening” and every-row inactivation wording for post-M3E behavior. **Its code was deleted in charter Phase 1 (D-66)**; for new work, ADR 0018 governs.
- [ADR 0013: Supplier operational commitments, Deadlines, exposure, and Arrangement ending](../adr/0013-supplier-operational-commitments-deadlines-exposure-and-ending.md) accepts source-shaped commitment openings and dispositions, Deposit Requirements, Deadlines, planning milestones, exposure, Needs attention, and Arrangement ending. [M3E](../planning/m3-supplier-planning/m3e-supplier-operational-control.md) is the shipped implementing slice (M3E.1–M3E.7b). **Its code was deleted in charter Phase 1 (D-66)**; for new work, ADR 0018 governs.
- [ADR 0014: Client offers, publication, and Supplier-source compatibility](../adr/0014-client-offers-publication-and-supply-compatibility.md) accepts Service Offer and Package identity, publication, activated-only M3 pins, Sales enabled versus computed eligibility, and the M5 Charge-posting handoff. [M4A](../planning/m4-offers-and-pricing/m4a-service-definitions-and-sources.md) ships unpublished drafts and source compatibility. [M4B](../planning/m4-offers-and-pricing/m4b-client-pricing-and-anonymous-preview.md) ships unpublished Client prices, the anonymous calculator, and optional indicative scenario economics. They are not implementation authority for later slices. [M4.0](../planning/m4-offers-and-pricing/m40-task-flow-and-contract.md) is the accepted task-flow gate. [M4C](../planning/m4-offers-and-pricing/m4c-packages-choices-and-client-terms.md) is shipped (unpublished Package drafts, package-only version ownership, choice templates, and Client terms). [M4D](../planning/m4-offers-and-pricing/m4d-publication-and-live-feasibility.md) is shipped (publication, Sales enabled, live feasibility, and M3 disclosure previews). [M4D.0](../planning/m4-offers-and-pricing/m4d0-narrow-group-departure-builder.md) and [M4D.0R](../planning/m4-offers-and-pricing/m4d0r-builder-interface-remediation.md) are shipped (M4D.0R interim UI). [M4D.1](../planning/m4-offers-and-pricing/m4d1-departure-composition-workspace.md) is Accepted; [Slice 1](../planning/m4-offers-and-pricing/m4d1-slice1-workspace-foundation.md) is shipped. [Slice 2A.1](../planning/m4-offers-and-pricing/m4d1-slice2a1-cruise-sailing-and-cabin-inventory.md) is shipped. [Slice 2A.2](../planning/m4-offers-and-pricing/m4d1-slice2a2-cruise-supplier-rates-and-occupancy-totals.md) is shipped. [Slice 2A.2R](../planning/m4-offers-and-pricing/m4d1-slice2a2r-cruise-supplier-rate-matrix.md) is shipped. Later sub-slices may amend this ADR for choice-rate linkage or Client price provenance—this ADR is not implementation authority for those until amended with the implementing slice. Do not implement M4E until an accepted plan names that work. Standing is the [planning index](../planning/README.md). **Its code was deleted in charter Phase 1 (D-66)**; for new work, ADR 0018 governs.
- [ADR 0015: Supplier agreement operational modeling boundary](../adr/0015-supplier-agreement-operational-boundary.md) accepts four Supplier-information classes. Operational definitions are facts DepartureDesk uses now. Contractual definitions require the present-domain-integrity test in that ADR. Agreement reference is version-owned wording. The [Supplier complexity rebaseline](../planning/m4-offers-and-pricing/supplier-complexity-rebaseline.md) is shipped: `SupplierDepositBasis`, structured Hotel attrition, and the structured deposit-refund clarification are `SupplierAgreementReference` rows of kind `deposit_derivation`, `attrition`, and `deposit_refund`. Fixed Deposit Requirements stay operational. `refund_due_on` is not a Deadline. This ADR does not authorize document storage. **Its code was deleted in charter Phase 1 (D-66)**; for new work, ADR 0018 governs.
- [ADR 0016: Agency time zone and optional offices](../adr/0016-agency-time-zone-and-optional-offices.md) supersedes ADR 0005's office time zones and required offices. One agency time zone; offices are optional and grant nothing.
- [ADR 0017: User types, per-user permissions and reseller users](../adr/0017-user-types-permissions-and-reseller-users.md) supersedes ADR 0005's roles. `agency_admin`, `staff` and `reseller` user types, five per-user grants, one action catalog, and a deny-by-default reseller scope.
- [ADR 0018: Supplier arrangement history by dated adjustment](../adr/0018-arrangement-history-by-dated-adjustment.md) supersedes ADRs 0008 and 0011–0013, and parts of 0010, for the new supplier layer. Do not build new features on the superseded ADRs; they govern shipped code until charter Phase 1 deletes it (D-66).
- [ADR 0019: Issued document storage](../adr/0019-issued-document-storage.md) renders issued documents once and stores them as immutable `document_versions` rows with the PDF in Active Storage. Active Storage framework routes stay off; every download goes through an authorized controller.
- [ADR 0002](../adr/0002-agency-tenancy-and-membership.md) and [ADR 0003](../adr/0003-membership-lifecycle-and-invitations.md) are **Superseded by ADR 0005**. Do not implement them.
